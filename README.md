# WEB: лабораторное приложение 3

Автор: Шубников А.А.

PHP-приложение с регистрацией, входом, профилем и публикациями с изображениями.
В `application/public/lab` находятся учебные демонстрации SQL injection, XSS
и проверки загрузки файлов, а также исправленные варианты.

**Только для изолированного учебного стенда.** Некоторые страницы намеренно
уязвимы. Не размещать приложение на публичном сервере и не вводить реальные
личные данные или пароли. Пароли `DEMO_ONLY_*` в схеме базы являются
искусственными учебными данными.

## Состав

- `application/`: PHP, CSS, JavaScript, изображение и SQL-схема.
- `application/config.example.php`: шаблон конфигурации без реальных паролей.
- `scripts/deploy.py`: развёртывание в локальной Kali.

Материалы проверок, скриншоты и подготовленные HTTP-запросы вынесены отдельно
и не включены в репозиторий.

## Запуск на учебной Kali

Нужны Python 3, Apache, PHP 8.1 или новее с PDO MySQL и MariaDB.
Из корня проекта запустить:

```bash
sudo python3 scripts/deploy.py application
```

Скрипт рассчитан на существующий стенд: адрес Kali `192.168.1.5`, HTTP-порт
`8083`, локальный порт базы `3307`. Он создаёт случайные пароли и рабочую
конфигурацию вне каталога публикуемых страниц. Адрес приложения:
`http://192.168.1.5:8083`. Временные службы после перезагрузки необходимо
запустить повторным выполнением команды развёртывания.

Просто открывать PHP-файлы в браузере нельзя: нужен сервер и база данных.
GitHub хранит исходники; GitHub Pages не запускает это PHP-приложение.

## Загрузка в GitHub

Создать пустой репозиторий в своём аккаунте, желательно приватный, без
автоматического README. В терминале из этой папки выполнить:

```bash
git status
git log -1 --oneline
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Заменить `USERNAME/REPOSITORY` своим адресом. Если `origin` уже существует,
сначала проверить его командой `git remote -v`, не добавлять повторно.
При отправке использовать штатную авторизацию Git; не записывать токен
в URL, исходники или README.

Для последующих изменений:

```bash
git add application scripts README.md .gitignore
git commit -m "Update application"
git push
```

Рабочий `config.php`, секреты базы, загруженные пользователями файлы,
скриншоты проверок и архивы исключены через `.gitignore`.
